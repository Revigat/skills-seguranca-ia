# Security skills for AI agents

A skill is a package of instructions, and sometimes scripts, that an AI agent starts to follow. Installing a skill hands a new procedure to a program that can already read files, use the network, and run into passwords. Read it before you install it.

If you only have a minute, go to [What to do today](#what-to-do-today).

## Why this matters

Two public reports, with links, show the size of the problem. They do not say that every skill is malware.

1) The study *Agent Skills in the Wild*, by Yi Liu et al., January 2026 ([arxiv.org/abs/2601.10338](https://arxiv.org/abs/2601.10338)), analyzed 31,132 skills taken from marketplaces. The authors report that 26.1% had at least one potentially dangerous pattern (8,126 skills). The paper itself says to read that figure as a pattern that deserves review, not as confirmed malware. In 5.2% (1,619 skills) the patterns were high severity and suggest malicious intent, such as obfuscated code, a hidden instruction, credential harvesting, or fetching an external script. The full author list is on the arXiv page.

2) In February 2026, Koi Security reviewed the 2,857 skills then published on ClawHub, the store for the OpenClaw assistant, and reported 341 malicious skills. Of those, 335 were part of the campaign named ClawHavoc. The trick was disguised as a prerequisite: on Windows, a password-protected zip; on macOS, a command to paste into Terminal. The Hacker News story of 2 February 2026 describes theft of browser passwords, SSH credentials, and API keys ([thehackernews.com](https://thehackernews.com/2026/02/researchers-find-341-malicious-clawhub.html)).

This repository is a free package to download, read, and install only what makes sense for you. It is not a certificate that a skill is safe. A scanner that finds nothing is not a certificate either.

## What is in the download

Each copied folder keeps the original license file, with the wording unchanged, and a `NOTICE` with the author, the URL, and the commit that was copied. Three folders have one example-string swap that GitHub push protection rejects: the Stripe documentation example in the Cisco scanner policy files became `sk_test_example`, a fake `ghp_` token in the `ctf-skills` test became `ghp_example`, and example `AIza` keys in the Trail of Bits APK scanner guide became `AIzaSyEXAMPLE`. The `NOTICE` in each folder records the swap. The `LICENSE` file did not change. There are no git submodules, so the GitHub button Code, then Download ZIP, includes the files.

The `avancado` folder is not the first step. It contains offensive techniques, only for a lab, a competition, or a system you have written permission to test. `cybersecurity-skills-mukul975` was written by Mahipal (GitHub mukul975). It was not made by Anthropic. The author's own README says so. This copy has 173 skills on defense, incident response, phishing, ransomware, compliance, and AI security. Even in those topics, some skills describe attacks (phishing simulation, exploit tooling, offensive model testing). The other 645 skills from that repository were left out so the download stays smaller. The left-out list is in the `NOTICE` in that folder. `ctf-skills`, by Lukasz Jagiello, is competition (CTF) material. Do not run `avancado/ctf-skills/scripts/install_ctf_tools.sh` until you have read the whole file.

The scanners `nvidia-skillspector` and `cisco-skill-scanner` include test folders (`tests/fixtures`, `evals`, `tests`) with samples built so the scanner can be checked, including harmful samples. Do not install those folders as skills.

## The built-in /security-review command in Claude Code

Claude Code already includes a command named `/security-review`. You do not download a file to make that command exist. Current Claude Code documentation describes it like this: it looks at the difference between your current branch and the default branch of the `origin` remote, and it points out risk such as injection, authentication flaws, and data exposure. It needs an `origin` remote. The page is [code.claude.com/docs/en/commands](https://code.claude.com/docs/en/commands).

Anthropic's help center describes the same command as an on-demand review inside the session, and it says automated review complements the practice you already have. It does not replace a person. Page: [support.claude.com](https://support.claude.com/en/articles/11932705-automated-security-reviews-in-claude-code).

The `claude-code-security-review` folder in this collection is a related piece. It is a GitHub Action: on a pull request, Claude comments with findings. It asks for an Anthropic API key, and it should only review pull requests from people you trust. The original README, copied in that folder, also shows how to customize the command: copy `.claude/commands/security-review.md` into your project's `.claude/commands/` folder and edit the text. The built-in command and the Action are related. One runs in your session. The other comments on GitHub.

## How to install

Download the ZIP with the GitHub button Code, then Download ZIP, and unzip it. Do not run a script from the ZIP until you have read the file.

A skill is the folder that contains `SKILL.md`. Copy that folder, not the whole repository, into your agent's skills directory. The file has to land at `<directory>/<skill-name>/SKILL.md`.

Install the version in the language you use with the agent: `revisar-skill-antes-de-instalar` or `review-skill-before-installing`. Both can sit side by side.

Do not copy the whole `avancado` folder on day one. And do not copy `tests` or `evals` from the scanners.

### Claude Code

Checked against: [code.claude.com/docs/en/skills](https://code.claude.com/docs/en/skills/) and [code.claude.com/docs/en/claude-directory](https://code.claude.com/docs/en/claude-directory).

1) For you, on every project on this machine: copy the skill folder to `~/.claude/skills/`. On Windows, `~` is your user folder.
2) For one project, and for teammates who clone it: copy the folder to `.claude/skills/` at the repository root.
3) Open Claude Code in that folder. Ask for something that matches the skill description, or call `/skill-name`.
4) Plugin marketplace, when the upstream publishes one. Official Claude Code docs use `/plugin marketplace add`. Trail of Bits documents, in its README, `/plugin marketplace add trailofbits/skills` for the GitHub repository. For a local copy, its README says to stand in the parent folder and use `/plugins marketplace add ./skills` (with an s in the first command). If one form fails on your version, try the other and check the docs. The `insecure-defaults` plugin has no `SKILL.md`. It is installed through that marketplace, not by dropping a loose `skills/` folder in place.

### Codex CLI and ChatGPT with skills

Checked against: [learn.chatgpt.com/docs/build-skills](https://learn.chatgpt.com/docs/build-skills) and [learn.chatgpt.com/docs/customization/overview](https://learn.chatgpt.com/docs/customization/overview).

1) In a project: `.agents/skills/<name>/SKILL.md`. Codex also looks at `.agents/skills` in parent folders, up to the repository root.
2) For you, on every project: `~/.agents/skills/<name>/SKILL.md`.
3) `~/.codex/skills` is still read. In March 2026 an OpenAI maintainer described that path as legacy and recommended `~/.agents/skills` ([openai/codex issue 14337](https://github.com/openai/codex/issues/14337)).
4) Trail of Bits documents `codex plugin marketplace add trailofbits/skills` and then `codex plugin add <plugin-name>@trailofbits`. That command is in its README, at the commit copied here. I did not find the same line on a separate OpenAI page. The folder path above is what OpenAI's documentation describes.

### Gemini CLI

Checked against: [geminicli.com/docs/cli/tutorials/skills-getting-started](https://geminicli.com/docs/cli/tutorials/skills-getting-started/) and [the discovery guide on GitHub](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/using-agent-skills.md).

1) For you: `~/.gemini/skills/<name>/SKILL.md`. The alias `~/.agents/skills/` also works.
2) In a project: `.gemini/skills/<name>/SKILL.md` or `.agents/skills/<name>/SKILL.md`.
3) The official tutorial says Gemini CLI finds `SKILL.md` at the skills directory root or one level down. A deeper file does not show up. Copy each skill folder to that level. Do not drop the whole Trail of Bits tree into `.gemini/skills`.
4) A project skill loads only if the folder is trusted. In Gemini CLI, use `/trust` and reopen the session if needed.
5) The command `gemini skills install <url>` installs into the user profile. `--scope workspace` installs into the project. The docs describe that command. I did not run it against this collection. Copying the folder is the path the tutorial shows for the file layout.
6) Check with `/skills list`. The frontmatter has to be the first thing in the file and it needs `name` and `description`.

### Cursor

Checked against: [cursor.com/docs/skills](https://cursor.com/docs/skills).

1) In a project: `.cursor/skills/<name>/SKILL.md` or `.agents/skills/<name>/SKILL.md`.
2) For you, on this machine: `~/.cursor/skills/<name>/SKILL.md` or `~/.agents/skills/<name>/SKILL.md`.

Grok (the coding agent), checked against: [docs.x.ai/build/features/skills-plugins-marketplaces](https://docs.x.ai/build/features/skills-plugins-marketplaces).

I did not find that path on the official Grok Bot page. Confirm it with the Bot before you rely on it. If the folder does not exist, use the generic method below.

### Generic method

This works for any agent that accepts a block of instructions and has no skills folder.

1) Open `SKILL.md`.
2) Copy the text that comes after the first `---` block.
3) Paste it into the conversation and say that these are the instructions for the task.
4) That lasts for that conversation. It does not install the skill for the next one.

## What to do today

1) Known source.
2) Read the `SKILL.md` and the scripts.
3) Run it through a scanner (SkillSpector or the Cisco skill-scanner, if one is already installed).
4) A command from a strange site in the terminal: delete the skill folder and do not run the command.

The skill `review-skill-before-installing` walks these four steps with you and returns `safe to install`, `review carefully`, or `do not install`. A clean scan does not mean the skill is safe.

## If installing is hard

If a step failed, open an Issue in this repository: [github.com/Revigat/skills-seguranca-ia/issues/new](https://github.com/Revigat/skills-seguranca-ia/issues/new).

Name the agent, the system (Windows, Mac, or Linux), the step you tried, and the error message. Do not paste a password, a key, a token, or the contents of `.env`.
