# Skills de segurança para agentes de IA

Uma skill é um pacote de instruções, e às vezes de scripts, que um agente de IA passa a seguir. Instalar uma skill é entregar um procedimento novo a um programa que já pode ler arquivo, usar a rede e esbarrar em senha. Olhe antes de instalar.

Se você só tem um minuto, vá para [O que fazer hoje](#o-que-fazer-hoje).

## Por que isso importa

Dois relatos públicos, com link, mostram o tamanho do problema. Eles não dizem que toda skill é malware.

1) O estudo *Agent Skills in the Wild*, de Yi Liu e colegas, de janeiro de 2026 ([arxiv.org/abs/2601.10338](https://arxiv.org/abs/2601.10338)), analisou 31.132 skills tiradas de marketplaces. Os autores relatam que 26,1% tinham ao menos um padrão potencialmente perigoso (8.126 skills). O próprio artigo pede para ler esse número como padrão que merece revisão, não como malware confirmado. Em 5,2% (1.619 skills) havia padrões de alta gravidade que sugerem intenção maliciosa, como código ofuscado, instrução escondida, coleta de credencial ou busca de script externo. A lista completa de autores está na página do arXiv.

2) Em fevereiro de 2026, a Koi Security revisou as 2.857 skills então publicadas no ClawHub, a loja do assistente OpenClaw, e apontou 341 skills maliciosas. Dessas, 335 faziam parte da campanha chamada ClawHavoc. O golpe vinha disfarçado de pré-requisito: no Windows, um zip com senha; no macOS, um comando para colar no Terminal. A matéria da The Hacker News, de 2 de fevereiro de 2026, descreve roubo de senhas do navegador, credenciais SSH e chaves de API ([thehackernews.com](https://thehackernews.com/2026/02/researchers-find-341-malicious-clawhub.html)).

Este repositório é um pacote gratuito para baixar, ler e instalar só o que fizer sentido para você. Não é um atestado de que uma skill seja segura. Um scanner que não acha nada também não é.

## O que tem aqui

Cada pasta copiada traz o arquivo de licença original, sem mudança no texto, e um `NOTICE` com autor, URL e o commit que foi copiado. Em três pastas houve uma troca só de string de exemplo que o GitHub recusa no push: a chave de exemplo da Stripe nos arquivos de política do scanner da Cisco virou `sk_test_example`, um token falso `ghp_` no teste do `ctf-skills` virou `ghp_example`, e chaves de exemplo `AIza` no guia do scanner de APK da Trail of Bits viraram `AIzaSyEXAMPLE`. O `NOTICE` de cada pasta registra a troca. O arquivo `LICENSE` não mudou. Não usamos submódulo do Git, então o botão Code, Download ZIP, no GitHub, traz os arquivos.

A pasta `avancado` não é o primeiro passo. Ela tem técnicas ofensivas, só para laboratório, competição ou sistema com permissão escrita. `cybersecurity-skills-mukul975` foi escrito por Mahipal (GitHub mukul975). Não foi feito pela Anthropic. O README original do autor diz isso. Esta cópia tem 173 skills de defesa, resposta a incidente, phishing, ransomware, compliance e segurança de IA. Mesmo nesses temas, algumas skills descrevem ataque (simulação de phishing, ferramenta de exploração, teste ofensivo de modelo). As outras 645 skills do repositório dele não entraram, para o download ficar menor. A lista do que ficou de fora está no `NOTICE` dessa pasta. `ctf-skills`, de Lukasz Jagiello, é material de competição (CTF). Não rode `avancado/ctf-skills/scripts/install_ctf_tools.sh` sem ler o arquivo inteiro.

Os scanners `nvidia-skillspector` e `cisco-skill-scanner` incluem pastas de teste (`tests/fixtures`, `evals`, `tests`) com exemplos feitos para o scanner errar ou acertar, inclusive exemplos nocivos. Não instale essas pastas como skill.

## O comando /security-review do Claude Code

O Claude Code já traz um comando chamado `/security-review`. Ele não é um arquivo que você precisa baixar para o comando existir. A documentação atual do Claude Code descreve o comando assim: ele olha a diferença entre o branch em que você está e o branch padrão do remoto `origin`, e aponta risco como injeção, falha de autenticação e exposição de dado. Ele precisa de um remoto `origin`. A página é [code.claude.com/docs/en/commands](https://code.claude.com/docs/en/commands).

O centro de ajuda da Anthropic descreve o mesmo comando como uma revisão sob demanda dentro da sessão, e diz que a revisão automática complementa a prática que você já tem. Não substitui uma pessoa. Página: [support.claude.com](https://support.claude.com/en/articles/11932705-automated-security-reviews-in-claude-code).

A pasta `claude-code-security-review` desta coleção é outra peça, da mesma família. É uma GitHub Action: em um pull request, o Claude comenta achados. Ela pede uma chave de API da Anthropic e só deve revisar pull request de gente em quem você confia. O README original, copiado na pasta, também mostra como personalizar o comando: copie `.claude/commands/security-review.md` para `.claude/commands/` do seu projeto e edite o texto. O comando embutido e a Action se parecem. Um roda na sua sessão. A outra comenta no GitHub.

## Como instalar

Baixe o ZIP pelo botão Code, Download ZIP, no GitHub, e descompacte. Não rode um script do ZIP antes de ler o arquivo.

Uma skill é a pasta que contém `SKILL.md`. Copie essa pasta, não o repositório inteiro, para o diretório de skills do seu agente. O arquivo precisa ficar em `<diretorio>/<nome-da-skill>/SKILL.md`.

Instale a versão no idioma em que você conversa com o agente: `revisar-skill-antes-de-instalar` ou `review-skill-before-installing`. As duas podem coexistir.

Não copie a pasta `avancado` inteira no primeiro dia. E não copie `tests` nem `evals` dos scanners.

### Claude Code

Fonte conferida: [code.claude.com/docs/en/skills](https://code.claude.com/docs/en/skills/) e [code.claude.com/docs/en/claude-directory](https://code.claude.com/docs/en/claude-directory).

1) Para você, em todos os projetos desta máquina: copie a pasta da skill para `~/.claude/skills/`. No Windows, `~` é a pasta do seu usuário.
2) Para um projeto, e para o time que clona o projeto: copie para `.claude/skills/` na raiz do repositório.
3) Abra o Claude Code nessa pasta. Peça algo que combine com a descrição da skill, ou chame `/nome-da-skill`.
4) Marketplace de plugin, quando a origem publica um. A documentação oficial do Claude Code usa `/plugin marketplace add`. A Trail of Bits documenta, no README dela, `/plugin marketplace add trailofbits/skills` para o repositório no GitHub. Para uma cópia local, o README dela manda estar na pasta pai e usar `/plugins marketplace add ./skills` (com s no primeiro comando). Se uma forma falhar na sua versão, tente a outra e confira a documentação. O plugin `insecure-defaults` não tem `SKILL.md`. Ele entra por esse marketplace, não pela cópia solta de uma pasta `skills/`.

### Codex CLI e ChatGPT com skills

Fonte conferida: [learn.chatgpt.com/docs/build-skills](https://learn.chatgpt.com/docs/build-skills) e [learn.chatgpt.com/docs/customization/overview](https://learn.chatgpt.com/docs/customization/overview).

1) No projeto: `.agents/skills/<nome>/SKILL.md`. O Codex também olha `.agents/skills` nas pastas acima, até a raiz do repositório.
2) Para você, em todos os projetos: `~/.agents/skills/<nome>/SKILL.md`.
3) `~/.codex/skills` ainda é lido. Em março de 2026, um mantenedor da OpenAI descreveu esse caminho como legado e recomendou `~/.agents/skills` ([openai/codex issue 14337](https://github.com/openai/codex/issues/14337)).
4) A Trail of Bits documenta `codex plugin marketplace add trailofbits/skills` e depois `codex plugin add <nome-do-plugin>@trailofbits`. Esse comando está no README dela, no commit copiado aqui. Eu não encontrei a mesma linha numa página separada da OpenAI. O caminho de pasta acima é o que a documentação da OpenAI descreve.

### Gemini CLI

Fonte conferida: [geminicli.com/docs/cli/tutorials/skills-getting-started](https://geminicli.com/docs/cli/tutorials/skills-getting-started/) e [o guia de descoberta no GitHub](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/using-agent-skills.md).

1) Para você: `~/.gemini/skills/<nome>/SKILL.md`. O atalho `~/.agents/skills/` também vale.
2) No projeto: `.gemini/skills/<nome>/SKILL.md` ou `.agents/skills/<nome>/SKILL.md`.
3) O tutorial oficial diz que o Gemini CLI encontra `SKILL.md` na raiz do diretório de skills ou um nível abaixo. Arquivo mais fundo não aparece. Copie cada pasta de skill para esse nível. Não jogue a árvore inteira da Trail of Bits dentro de `.gemini/skills`.
4) Skill de projeto só carrega se a pasta for confiável. No Gemini CLI, use `/trust` e abra de novo se precisar.
5) O comando `gemini skills install <url>` instala no perfil do usuário. `--scope workspace` instala no projeto. A documentação descreve esse comando. Eu não executei esse comando contra esta coleção. Copiar a pasta é o caminho que o tutorial mostra com o layout do arquivo.
6) Confira com `/skills list`. O frontmatter tem de ser a primeira coisa do arquivo e precisa ter `name` e `description`.

### Cursor

Fonte conferida: [cursor.com/docs/skills](https://cursor.com/docs/skills).

1) No projeto: `.cursor/skills/<nome>/SKILL.md` ou `.agents/skills/<nome>/SKILL.md`.
2) Para você, nesta máquina: `~/.cursor/skills/<nome>/SKILL.md` ou `~/.agents/skills/<nome>/SKILL.md`.
3) O Cursor também lê, por compatibilidade, `.claude/skills/`, `.codex/skills/`, `~/.claude/skills/` e `~/.codex/skills/`.
4) Ele percorre subpastas. O jeito simples continua sendo copiar a pasta que contém o `SKILL.md`.
5) No chat do Agent, digite `/` e procure o nome. A documentação diz que skill em `~/.cursor/skills/` fica na sua máquina até você sincronizar para Cloud Agents, e que o Cursor não copia `~/.agents/skills/` nem skill local não sincronizada para Cloud Agents, sessão remota ou worker self-hosted.

### Grok e Grok Bot

Fonte do Grok (o agente de código), conferida: [docs.x.ai/build/features/skills-plugins-marketplaces](https://docs.x.ai/build/features/skills-plugins-marketplaces).

1) No projeto: `.grok/skills/<nome>/SKILL.md` (a busca sobe até a raiz do repositório).
2) Para você: `~/.grok/skills/<nome>/SKILL.md`.
3) A mesma página diz que o Grok também lê `~/.agents/skills/` e, por compatibilidade com Claude Code, as skills nas pastas do Claude.

Fonte do Grok Bot (o produto de conversa), conferida: [docs.x.ai/grok-bot/skills-routines-and-automations](https://docs.x.ai/grok-bot/skills-routines-and-automations).

Essa página não descreve uma pasta de `SKILL.md`. Ela manda pedir ao Bot para salvar o processo como skill, e ligar a skill em Connect apps, em Private skills.

Existe um caminho citado por instaladores da comunidade e pela matriz de alvos do Agent Package Manager ([microsoft.github.io/apm](https://microsoft.github.io/apm/reference/targets-matrix/), página com data de 23 de novembro de 2026): `~/agent-data/workflows/<nome>/SKILL.md` no computador do Bot. Eu não encontrei esse caminho na página oficial do Grok Bot. Confirme com o Bot antes de depender dele. Se a pasta não existir, use o jeito genérico abaixo.

### Jeito genérico

Serve para qualquer agente que aceite um bloco de instruções e não tenha pasta de skill.

1) Abra o `SKILL.md`.
2) Copie o texto que vem depois do primeiro bloco entre `---`.
3) Cole na conversa e diga que estas são as instruções da tarefa.
4) Isso vale para aquela conversa. Não deixa a skill instalada na próxima.

## O que fazer hoje

1) Fonte conhecida.
2) Ler o `SKILL.md` e os scripts.
3) Passar no scanner (SkillSpector ou o skill-scanner da Cisco, se já estiver instalado).
4) Comando de site estranho no terminal: apague a pasta da skill e não rode o comando.

A skill `revisar-skill-antes-de-instalar` faz esses quatro passos com você e devolve `seguro para instalar`, `revisar com cuidado` ou `nao instalar`. Um scanner limpo não garante que a skill seja segura.

## Dificuldade para instalar

Se um passo falhou, abra uma Issue neste repositório: [github.com/Revigat/skills-seguranca-ia/issues/new](https://github.com/Revigat/skills-seguranca-ia/issues/new).

Diga o nome do agente, o sistema (Windows, Mac ou Linux), o passo que você tentou e a mensagem de erro. Não cole senha, chave, token nem conteúdo de `.env`.
